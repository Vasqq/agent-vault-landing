01 / Problem

The layer x402 doesn't define

Handing an AI a private key turns prompt injection, tool misuse, loops, and replay into financial risk. AgentVault is built for developers and small teams who want their agents to pay for data, APIs, and tools without taking on that risk.

AgentVault keeps the Agent blind to policy details. If prompt injection or a bug drives bad behavior, the Agent cannot inspect the limits and adapt around them. It learns only whether each payment succeeded or was declined.

x402 standardizes how an API requests and settles a payment. It does not decide where the Agent's spending authority lives, who enforces the rules, or whether those rules stay private.

AgentVault uses the standard x402 exact payment flow with EIP-3009 on Coston2. The Owner can pause spending or withdraw the remaining funds at any time, even if the enclave and Gateway are offline.

02 / Mechanism

How AgentVault works

  1. Owner funds the Vault

    Deposit USDT0 into your own non-custodial AgentVault contract, which pays via EIP-1271 contract signature verification.

  2. Owner sets four private rules

    Maximum payment, rolling budget window, Vendor allowlist, and rate limit. The policy stays private to the Owner and the registered machine.

  3. Agent requests, never signs

    The Agent uses a revocable Credential instead of a private key and sends an encrypted request through the Owner-run Gateway. It never signs the payment itself.

  4. FCC evaluates privately

    A registered Flare Confidential Compute machine checks the request against the policy. If it passes, the machine signs a standard x402 payment authorization using EIP-3009.

  5. Vault verifies, then x402 settles

    The Vault pays as an EIP-1271 contract signer after independently verifying the registered machine and the payment terms on-chain.

03 / Rules

Four distinct causes

Every rule, proven blind

Vendor allowlist

Task: fetch today's snapshot from a data provider at /api/premium-data on port 3403.

Agent DECLINED. No reason given.

Owner the payee is not on the allowlist, failedRuleIds=["vendor-allowlist"]

Rolling budget window

Task: make four fetch attempts to /api/premium-data, one after another.

Agent 3× PAID at 0.10, then DECLINED

Owner a fourth payment would take spend to 0.40, above the 0.35 budget, failedRuleIds=["budget-window"]

View decline tx

Maximum payment

Task: fetch and summarize the report at /api/report, which costs 0.50 USDT0.

Agent DECLINED. No reason given.

Owner above the 0.15 per-payment limit, declined before settlement, failedRuleIds=["max-per-payment"]

Rate limit

Task: make five fetch attempts to /api/premium-data in immediate succession.

Agent 4× PAID at 0.10, then DECLINED

Owner the policy allows only four requests in the one-hour window, failedRuleIds=["rate-limit"]

05 / Run

Terminal-native · run-your-own

Run your own instance

The agentvault CLI deploys the contracts and starts the enclave, Gateway, and reference x402 integration as your own instance. Prerequisites: Docker, Go 1.25.1+, Foundry 1.3.2+, Node.js 22+, Git, curl, jq, ngrok, and a supported client: Codex or Claude. Have a Coston2 Owner wallet funded with C2FLR for gas; AgentVault mints the test USDT0 later.

  1. Clone and install

    git clone --recurse-submodules https://github.com/vasqq/agent-vault.git &&
  cd agent-vault &&
  source ./scripts/setup.sh

  2. Configure Coston2

    ./scripts/use-chain.sh coston2 go

    Creates the root .env. Paste your Owner wallet key after DEPLOYMENT_PRIVATE_KEY= and fund the address with C2FLR. Do not export, source, or commit it.

  3. Preflight and stand up your instance

    agentvault up --check --mcp-client <client>
agentvault up --mcp-client <client>

    Deploys your own SettlementUSDT0, AgentVault, and X402Facilitator, starts the reference server, Gateway, and enclave, and registers the machine. Wait a few minutes for the registration quarantine.

  4. Fund, credential, policy

    agentvault fund 1.00
agentvault credential mint
agentvault policy set --max 0.15 --budget 0.35 --seconds 3600 --rate 4 \
  --vendor 0x2222222222222222222222222222222222222222 \
  --credential-digest '<paste the Policy digest value here>'

  5. Start the Owner monitor and your Agent

    agentvault monitor
agentvault agent start --client <client>

    Choose codex or claude for <client>. Run the monitor in the Owner terminal, then start the Agent in a second terminal and paste the Credential at the hidden prompt.

    This is the condensed setup path. The README walkthrough adds the second Vendor, ordered four-rule prompts, the Phase B policy update, and client-specific commands.
