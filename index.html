01 / Problem

The layer x402 doesn't define

Handing an AI a private key turns prompt injection, tool misuse, loops, and replay into financial risk. AgentVault is built for developers and small teams who want their agents to pay for data, APIs, and tools without taking on that risk.

AgentVault keeps the Agent blind to policy details. If prompt injection or a bug drives bad behavior, the Agent cannot inspect the limits and adapt around them. The agent knows only whether each payment succeeded or was declined.

x402 standardizes how an API requests and settles a payment. It does not decide where the Agent's spending authority lives, who enforces the rules, or whether those rules stay private.

AgentVault uses the standard x402 exact payment flow with EIP-3009 on Coston2. The Owner can pause spending or withdraw the remaining funds at any time, even if the enclave and Gateway are offline.

02 / Mechanism

How AgentVault works

  1. Owner funds the Vault

    Deposit USDT0 into your own non-custodial AgentVault contract, which pays via EIP-1271 contract signature verification.

  2. Owner sets four private rules

    Maximum payment, rolling budget window, Vendor allowlist, and rate limit. The policy stays private to the Owner and the registered machine.

  3. Agent requests, never signs

    The Agent uses a revocable Credential instead of a private key and sends an encrypted request through the Owner-run Gateway. It never signs the payment itself.

  4. FCC evaluates privately

    A registered Flare Confidential Compute machine checks the request against the policy. If it passes, the machine signs a standard x402 payment authorization using EIP-3009.

  5. Vault verifies, then x402 settles

    The Vault pays as an EIP-1271 contract signer after independently verifying the registered machine and the payment terms on-chain.

05 / Run

Self-host AgentVault

Run AgentVault to see the boundary work in your own environment: an Agent can make approved purchases without receiving a private key, while you keep the policy and can stop spending or withdraw funds.

The walkthrough deploys your instance, then drives four policy rules against standard x402 endpoints. The Agent sees only whether a payment went through; the Owner monitor verifies the result and shows the private reason for a decline. Together, the successful payments and stopped requests show the settlement path and policy checks working end to end.

Prerequisites

Install these before cloning AgentVault.

  • Docker
  • Go 1.25.1+
  • Foundry 1.3.2+
  • Node.js 22+
  • Git
  • curl
  • jq
  • ngrok
  • Codex or Claude

Have a Coston2 wallet funded with C2FLR for gas. Get C2FLR from the Coston2 faucet.

Setup

Use two terminal windows: Terminal 1: Owner runs steps 1 through 8 and keeps the Owner monitor open. Open Terminal 2: Agent only for step 9, in the same agent-vault checkout. During the walkthrough, submit tasks in Terminal 2 and watch verified policy results in Terminal 1.

  1. Clone and install

    git clone --recurse-submodules https://github.com/vasqq/agent-vault.git &&
  cd agent-vault &&
  source ./scripts/setup.sh

    Start in Terminal 1 (Owner). setup.sh installs the contract toolchain, x402 reference, and AgentVault CLI, then updates this shell’s PATH.

  2. Configure Coston2

    ./scripts/use-chain.sh coston2 go

    This creates the root .env and configures Coston2 for AgentVault.

    1. Open the new .env in the repository root and find DEPLOYMENT_PRIVATE_KEY=.
    2. Paste the Owner wallet’s private key after =, then save the file.
    3. Do not export, source, or commit this key, and do not reuse it for any service.
    4. Copy the wallet’s public address and fund it with C2FLR from the Coston2 faucet. A fresh run deploys three contracts and registers a TEE machine.

  3. Run preflight

    agentvault up --check --mcp-client codex
    agentvault up --check --mcp-client claude

    This checks that your system is ready to run AgentVault and that all prerequisites are met.

  4. Stand up your instance

    agentvault up --mcp-client codex
    agentvault up --mcp-client claude

    This deploys your own SettlementUSDT0, AgentVault, and X402Facilitator; starts the reference server, Gateway, and enclave; registers the machine; and writes ~/.agentvault/instance.json.

    Wait a few minutes after completion for the registration quarantine.

  5. Fund your Vault

    agentvault fund 1.00

    This deposits 1.00 test USDT0 into AgentVault.

  6. Mint a Credential

    agentvault credential mint

    The command prints two values. Save them somewhere secure:

    • Credential: 64 lowercase hex characters with no 0x prefix. Paste it into the Agent launcher’s hidden prompt in step 9.
    • Policy digest: 0x followed by 64 lowercase hex characters. Paste it into --credential-digest in step 7 and again in the Phase B policy update.

  7. Set your private policy

    agentvault policy set \
  --max 0.15 \
  --budget 0.35 \
  --seconds 3600 \
  --rate 4 \
  --vendor 0x2222222222222222222222222222222222222222 \
  --credential-digest '<paste the Policy digest value here>'

    This policy allows:

    • maximum payment (--max 0.15): up to 0.15 USD per payment
    • rolling budget window (--budget 0.35, --seconds 3600): up to 0.35 USD during any one-hour window
    • Vendor allowlist (--vendor): payments only to the listed address
    • rate limit (--rate 4, --seconds 3600): up to four approved payments during that same one-hour window

  8. Start the Owner view

    ./scripts/agentvault-vendors.sh --wait-ready

    Wait for Second vendor ready: http://localhost:3403 (token/facilitator/payee identity verified). The Vendor stays running in the background.

    agentvault monitor

    Leave Terminal 1 open with the Owner monitor running.

  9. Start your Agent

    agentvault agent start --client codex
    agentvault agent start --client claude

    Open Terminal 2 in the same checkout. Do not source .env or start the coding client directly. The launcher configures MCP and opens a hidden prompt; paste the Credential from step 6, not the Policy digest. Leave Terminal 2 open after the coding agent starts.

06 / Delta

Built during Flare Summer Signal

  • The Owner keeps the funds in an AgentVault contract, sets a private policy, and can pause spending or withdraw funds at any time.
  • The Agent gets a Credential instead of a payment-signing key. It can request a payment but cannot sign or send a transaction, and learns only whether the request succeeded or was declined.
  • A registered Flare FCC machine checks the private vendor allowlist, maximum payment, rolling budget window, and rate limit before it signs an approved EIP-3009 authorization.
  • The Vault pays through standard x402 as an EIP-1271 contract signer, after it verifies the registered machine and the exact payment terms on-chain.

07 / Roadmap

What's next

AgentVault is self-hosted today. Next comes a hosted option and a small fee on approved payments.

  1. 01 / Hosting

    Hosted AgentVault

    Teams would connect an agent to a hosted AgentVault instance instead of deploying and operating the full stack themselves. They could set spending rules from a web app. Running your own instance stays supported.

  2. 02 / Pricing

    A fee on approved payments

    Charge a small, clear fee only on payments AgentVault approves. Show it up front and price it in line with comparable payment infrastructure.

Autonomy for the agent. Control for the Owner.
